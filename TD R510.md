## Exercice 1 : Modélisation

### a) Quelle base de données préconisez-vous ? Pourquoi ?

Je préconise une **base de données orientée graphe** (Neo4j), car :
- Le modèle est naturellement un **réseau de relations** (personnes ↔ personnes, personnes ↔ entreprises, personnes ↔ compétences, entreprises ↔ compétences).
- Les requêtes impliquent des **parcours de graphe** (amis d'amis, compétences recherchées par une entreprise, historique de postes) qui seraient coûteux en SQL (jointures multiples).
- Les relations portent des **propriétés** (année de début, niveau de maîtrise, poste), ce qui est natif en graphe.
- L'évolution du schéma est souple (pas de migration lourde).

### b) Nœuds (labels) et propriétés

| Label | Propriétés |
|---|---|
| **Personne** | `nom`, `ville` (+ éventuellement `age`) |
| **Entreprise** | `nom`, `secteur` |
| **Competence** | `nom` (ex. SQL, Python, Neo4j) |

> On peut aussi envisager un label `Poste` si l'on veut historiser (voir question e).

### c) Relations, type, direction, propriétés

| Relation | Direction | Propriétés |
|---|---|---|
| **TRAVAILLE_POUR** | `(Personne)-[:TRAVAILLE_POUR]->(Entreprise)` | `poste`, `annee_debut` |
| **CONNAIT** | `(Personne)-[:CONNAIT]->(Personne)` | `depuis` (année) |
| **MAITRISE** | `(Personne)-[:MAITRISE]->(Competence)` | `niveau` (1 à 5) |
| **RECHERCHE** | `(Entreprise)-[:RECHERCHE]->(Competence)` | — |

### d) Dessin du graphe pour l'exemple

```
(Personne {nom:"Laurine", ville:"..."})
   |--[:TRAVAILLE_POUR {poste:"data engineer", annee_debut:2021}]--> (Entreprise {nom:"Arm", secteur:"..."})
   |--[:MAITRISE {niveau:5}]--> (Competence {nom:"Python"})
   |--[:CONNAIT {depuis:...}]--> (Personne {nom:"Jibril"})
                                      |--[:TRAVAILLE_POUR {poste:..., annee_debut:...}]--> (Entreprise {nom:"Arm"})

(Entreprise {nom:"Arm"}) --[:RECHERCHE]--> (Competence ...)   (si Arm recherche des compétences)
```

Représentation textuelle :
```
Laurine ──TRAVAILLE_POUR(poste="data engineer", annee_debut=2021)──► Arm
Laurine ──MAITRISE(niveau=5)──► Python
Laurine ──CONNAIT(depuis=…)──► Jibril
Jibril ──TRAVAILLE_POUR(…)──► Arm
```

### e) Conserver l'historique des postes (plusieurs postes dans la même entreprise)

Deux approches :

1. **Approche relation directe avec propriétés multiples** : ajouter une propriété liste `postes: [{poste, annee_debut, annee_fin}]` sur la relation `TRAVAILLE_POUR`. Simple mais peu interrogeable.
2. **Approche recommandée (nœud intermédiaire)** : transformer la relation en un **nœud `Poste`** :
   ```
   (Personne)-[:OCCUPE]->(Poste {intitule, annee_debut, annee_fin})-[:DANS]->(Entreprise)
   ```
   On peut ainsi avoir plusieurs `Poste` pour la même personne dans la même entreprise, et historiser proprement (dates de début/fin, poste courant).

### f) Combien de tables en relationnel ? Lesquelles sont des tables de jointures ?

Avec le modèle de base (sans historisation), on aurait **6 tables** :

1. **Personne** (id, nom, ville)
2. **Entreprise** (id, nom, secteur)
3. **Competence** (id, nom)
4. **Travaille_pour** (id_personne, id_entreprise, poste, annee_debut) → **table de jointure** Personne–Entreprise
5. **Connait** (id_personne1, id_personne2, depuis) → **table de jointure** Personne–Personne (auto-relation)
6. **Maitrise** (id_personne, id_competence, niveau) → **table de jointure** Personne–Competence
7. **Recherche** (id_entreprise, id_competence) → **table de jointure** Entreprise–Competence

Donc **3 tables d'entités** (Personne, Entreprise, Competence) + **4 tables de jointures** (Travaille_pour, Connait, Maitrise, Recherche) = **7 tables** au total.  
Si l'on compte les entités seules : 3 tables ; les 4 autres sont des **tables de jointure** (relations many-to-many porteuses de propriétés).

> Remarque : `Connait` est une jointure réflexive (Personne–Personne). `Travaille_pour` et `Maitrise` portent des propriétés (poste, année, niveau), ce qui est typique des tables de jointure enrichies.

## Préparation

### a) Créer et lancer le conteneur Neo4j

```bash
docker run -d --name neo4j -p 7474:7474 -p 7687:7687 \
  -e NEO4J_AUTH=neo4j/password123 neo4j:5
```

### b) Se connecter à l'éditeur web

- URL : http://localhost:7474
- Connect URL : `neo4j://localhost:7687`
- Username : `neo4j`
- Password : `password123`

### c) Ouvrir cypher-shell dans le conteneur

```bash
docker exec -it neo4j cypher-shell -u neo4j -p password123
```
Chaque requête se termine par `;`.

## Exercice 2 : Premières manipulations

### 1 - Création

#### a) Créer cinq nœuds de type Personne

```cypher
CREATE (leo:Personne {nom: "Léo", age: 25, ville: "Nice"});
CREATE (sofian:Personne {nom: "Sofian", age: 20, ville: "Cannes"});
CREATE (yasmine:Personne {nom: "Yasmine", age: 32, ville: "Paris"});
CREATE (zoe:Personne {nom: "Zoé", age: 16, ville: "Nice"});
CREATE (victor:Personne {nom: "Victor", age: 27, ville: "Antibes"});
```

Ou en une seule requête :

```cypher
CREATE
  (:Personne {nom: "Léo", age: 25, ville: "Nice"}),
  (:Personne {nom: "Sofian", age: 20, ville: "Cannes"}),
  (:Personne {nom: "Yasmine", age: 32, ville: "Paris"}),
  (:Personne {nom: "Zoé", age: 16, ville: "Nice"}),
  (:Personne {nom: "Victor", age: 27, ville: "Antibes"});
```

#### b) Créer des relations CONNAIT

Exemple : Léo connaît Yasmine et Zoé.

```cypher
MATCH (leo:Personne {nom: "Léo"}), (yasmine:Personne {nom: "Yasmine"})
CREATE (leo)-[:CONNAIT]->(yasmine);

MATCH (leo:Personne {nom: "Léo"}), (zoe:Personne {nom: "Zoé"})
CREATE (leo)-[:CONNAIT]->(zoe);
```

On peut ajouter d'autres relations (Sofian connaît Léo, Yasmine connaît Sofian, etc.) :

```cypher
MATCH (sofian:Personne {nom: "Sofian"}), (leo:Personne {nom: "Léo"})
CREATE (sofian)-[:CONNAIT]->(leo);

MATCH (yasmine:Personne {nom: "Yasmine"}), (sofian:Personne {nom: "Sofian"})
CREATE (yasmine)-[:CONNAIT]->(sofian);
```

### 2 - Requêtes de base

#### a) Sélectionner tous les nœuds de type Personne

```cypher
MATCH (p:Personne) RETURN p;
```

#### b) Sélectionner le nœud "Sofian" et afficher ses propriétés

```cypher
MATCH (p:Personne {nom: "Sofian"}) RETURN p;
```
(ou `RETURN p.nom, p.age, p.ville`)

#### c) Sélectionner toutes les relations CONNAIT

```cypher
MATCH ()-[r:CONNAIT]->() RETURN r;
```

### 3 - Requêtes avancées

#### a) Toutes les personnes que Yasmine connaît

```cypher
MATCH (yasmine:Personne {nom: "Yasmine"})-[:CONNAIT]->(ami:Personne)
RETURN ami;
```

#### b) Toutes les personnes qui ne connaissent personne

```cypher
MATCH (p:Personne)
WHERE NOT (p)-[:CONNAIT]->(:Personne)
RETURN p;
```

#### c) Toutes les personnes qui ont plus de deux amis

```cypher
MATCH (p:Personne)-[:CONNAIT]->(ami:Personne)
WITH p, count(ami) AS nb_amis
WHERE nb_amis > 2
RETURN p, nb_amis;
```

### 4 - Mise à jour des données

#### a) Modifier l'âge de "Zoé" à 25

```cypher
MATCH (zoe:Personne {nom: "Zoé"})
SET zoe.age = 25;
```

#### b) Ajouter une propriété ville à "Victor" = "Menton"

```cypher
MATCH (victor:Personne {nom: "Victor"})
SET victor.ville = "Menton";
```
> Si Victor avait déjà une ville (Antibes), `SET` remplace la valeur. Pour ajouter sans écraser, on utiliserait `SET victor.ville = "Menton"` de toute façon (la propriété existe déjà ici).

### 5 - Suppression des données

#### a) Supprimer la relation CONNAIT entre "Léo" et "Zoé"

```cypher
MATCH (leo:Personne {nom: "Léo"})-[r:CONNAIT]->(zoe:Personne {nom: "Zoé"})
DELETE r;
```

#### b) Supprimer le nœud "Victor"

```cypher
MATCH (victor:Personne {nom: "Victor"})
DELETE victor;
```
> ⚠️ Si Victor a des relations, `DELETE` échoue. Il faut d'abord les supprimer ou utiliser `DETACH DELETE` :
```cypher
MATCH (victor:Personne {nom: "Victor"})
DETACH DELETE victor;
```

## Récapitulatif des commandes Cypher utiles

| Opération | Requête |
|---|---|
| Créer nœud | `CREATE (p:Personne {nom:"..."})` |
| Créer relation | `MATCH (a),(b) CREATE (a)-[:CONNAIT]->(b)` |
| Lire | `MATCH (p:Personne) RETURN p` |
| Filtrer | `WHERE p.age > 20` |
| Agréger | `WITH p, count(ami) AS n WHERE n > 2` |
| Mettre à jour | `SET p.age = 25` |
| Supprimer relation | `MATCH ()-[r:CONNAIT]->() DELETE r` |
| Supprimer nœud | `MATCH (p) DETACH DELETE p` |

N'hésite pas si tu veux que je détaille une partie (par exemple le modèle avec nœud `Poste` ou les requêtes de parcours plus complexes).
